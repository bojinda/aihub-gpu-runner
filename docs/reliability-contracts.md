# Reliability contracts

Status: offline candidate. No production authority is granted by this document.



The following generic contracts are acceptable for the canonical source documentation, with test qualification and remaining gates stated honestly:

- **D1:** Ordinary cleanup may discard a contaminated sample and correlate a fully attested current probe within the original owned-work deadline; it must retain the lease through positive exit and fresh stable proof. Missing historical executable/lifetime identity is not reconstructed. Manual eligibility remains the existing explicit class; unknown/sparse historical classes and automatic same-boot Ollama retirement remain disabled. Any future broader manual contract requires separate review and exact operator authorization.
- **D2:** CPU startup may preserve the bytes of an exactly bound completed retained Ollama job; this is evidence preservation, not execution adoption, quiescence proof or lease release. Installation additionally requires qualified completed/inactive handover and rollback, original lock identities and unchanged durable ownership/history. Owner-free installation is not required merely to preserve a retained lease. Backend actions and production restart require separate authorization.
- **D3:** Build from clean canonical source with explicit per-component provenance. Generic configuration and synthetic tests are public; operational identities, private settings, raw evidence and deployment manifests are private. Public-history remediation and release/deployment are separate actions, never inferred from source reconstruction.
- **D4:** Idle recovery uses one monotonic request budget below the shortest transport timeout and remaining signed approval lifetime. Coordination waits consume one aggregate bounded interval, name contention and release acquired prefixes on failure. Physical locks are original identity-checked zero-wait acquisitions. Jobs precedes admission; callbacks under admission cannot reacquire jobs/admission. Exact post-intent uncertainty is Verify-only, and deadline expiration never authorizes a retry, lease clear or fence removal.


## Implementation boundaries

The ordinary correlation clock is integer Linux CLOCK_BOOTTIME in /proc start-time ticks. A second census must prove the unchanged exact existing probe role, parent, executable/argv, namespaces, cgroup, image/container generation and a birth strictly before the query start minus one tick. A correlated compute sample is discarded. This cannot authenticate an older stale GPU row's ancestry, nor a vanished historical PID. Positive exit followed by complete stable samples remains required.

Initial verification and every final publication/release check share the original cleanup deadline. They repeat observations only, never inference or model unload. The final ownership-mutex callback is local binding validation, not a callback that reacquires jobs or runs external observations.

Manual v1 keeps its existing supported class and exact confirmation. Its internal native callback takes fresh proof while both original physical locks are held; locks remain nonblocking. It persists that proof under the already-held admission lock before native atomic settlement. Lost acknowledgment remains Verify-only. This strengthens the installed class and does not certify direct/unmanaged producers have been excluded.

The request uses a nominal 50-second cooperative deadline, capped by the signed monotonic and wall-clock ticket lifetime with one-second reserve. Coordination acquisition has one aggregate second. Inner jobs/admission waits consume the remaining budget and report named busy outcomes. Original physical locks do not wait. Filesystem syscalls, JSON decoding and OS scheduling cannot be forcibly preempted by this Python budget; no hard real-time latency is claimed. All uncertainty after durable intent retains the fence.

## Proposed additional manual authority — DISABLED

No current error-string addition or automatic retirement is implemented. A broader completed/inactive class would require separately approved evidence rules: exact single owner/job/request/boot/scope/policy and original locks; independently excluded producers; no active supervision, handoffs, permits, pending work or residency; complete current process/container/driver/GPU observations; explicit handling of incomplete historical PID evidence; fresh stable proof under native locks at commit; signed exact administrator confirmation; one native failed/no-replay disposition and durable attempt; Verify-only after uncertainty. Bounded diagnostics are not a complete authoritative lifetime ledger. Sparse historical evidence must not silently become an eligibility ticket. The independent review has not accepted this new authority.

## Retained-state handover and rollback

Same-boot completed inactive Ollama evidence is preserved by actual Runner startup and automatic recovery; preservation does not prove physical idle or authorize release. A fresh attended window must exclude producers and active supervision and verify all exact bindings, source versions and original locks. No migration, new journal, replay or historical transition is needed.

An older runner that rewrites retained evidence is not an admissible rollback while that lease remains. Before any successor launch, failure leaves the CPU service stopped under containment for review; after launch or any recovery uncertainty, use exact read-only verification. Never restore old journals or start an unqualified predecessor over retained ownership. A rollback after verified owner-free settlement still needs source/settings verification and separate attended authorization. Restore recorded ingress states on completion or abort; restoration is not an inference trigger.
